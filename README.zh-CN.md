# 项目通用规范

[English](README.md) | [简体中文](README.zh-CN.md)

> 新建或初始化项目时自动生效的两条强制规则，不用每次重新交代。

## 这是什么

这不是一份风格指南，也不是一张偏好清单。规则只有两条，两条都是因为违反过、出过真问题才写下的。

价值在于约束力度。一份三十条的规范会被无视。两条每次都落实的规则，才真的会改变结果。

## 为什么开源

每一个新项目开始的时候，都要重复做同样两次纠正。与其一直纠正，不如把它写成会自动生效的规则。

里面没有属于我们的东西 —— 规则讲的是怎么做事情，不是做什么事情。这套东西里最容易迁移的就是它。

## 能做什么

- **规则一 —— 只认官方来源。** 事实、数据、规范、工具用法，只能来自官方文档、官方仓库、官方公告，或者标准组织与政府来源。个人博客、论坛、问答社区、非官方转载、营销软文，都不作为事实依据。
- **规则二 —— 先分类，再建索引。** 建项目时按分类把目录立起来，并在项目根部生成一份结构文档，让布局一眼可见，而不是一层层点进去看。

## 环境要求

无 —— 纯约定，不含脚本

## 安装

```bash
git clone https://github.com/<你的用户名>/project-conventions.git
```

然后把整个目录放进技能目录：

| 系统 | 路径 |
|---|---|
| Windows | `C:\Users\<你>\.workbuddy\skills\project-conventions\` |
| macOS / Linux | `~/.workbuddy/skills/project-conventions/` |

没有构建步骤，重启对话即生效。

## 怎么用

新建项目、或在空目录里开始任务时会自动生效。也可以直接点名：

- "初始化这个项目"
- "把目录结构建起来"
- "新建项目"

它会按分类把目录立好，并写出根部的结构索引。

## 注意与边界

1. **故意写得很短。** 两条规则会被执行，一长串会被略过。想加条款的时候要克制。
2. **规则一是承重的那一条。** 大部分错误结论，往回追都追到一个看起来很像权威的二手来源上。坚持一手来源，直接消掉一整类错误。
3. **规则二解决的是导航，不是整洁。** 索引的意义是让人不开目录树也能看懂项目。
4. **规范不等于强制。** 没人拦着你把文件丢到错误的目录里。规范塑造的是默认路径，而实际被用的就是默认路径。
